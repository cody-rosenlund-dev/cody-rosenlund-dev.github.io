01 / PRODUCT ENGINEERING

SPS COMMERCE · TYPESCRIPT / KOTLIN

Giving customers control
of their data mappings.

I led development of Cross Reference, a self-service feature that lets customers maintain trading-partner mappings without contacting Support. I built most of the TypeScript UI and Kotlin backend.

4 mapping typesOne reusable implementation.
Inside the project +

The problem

Customers needed to maintain the relationships between their data and trading-partner values. Those changes previously required contacting Support.

My approach

I designed a generic implementation for connections, locations, carriers, and charges and allowances. I worked with Product on requirements and delivery updates, coordinated integration with other engineering teams, and used internal feedback to improve the experience.

The result

Customers can configure their own mappings, and the reusable design makes additional mapping types easier to introduce.

02 / FRONTEND ARCHITECTURE

SPS COMMERCE · REACT / TYPESCRIPT

Building a shared foundation.

I proposed and independently completed React rewrites of account administration and ERP credential-management applications, bringing them into a shared TypeScript monorepo.

The work

Completed in 2022–2023, the rewrites modernized two existing applications while establishing patterns that could be shared across the frontend ecosystem.

Architecture decisions

I introduced shared types, API clients, Storybook, and React Query across six UIs, including four embedded in larger applications. Moving UI configuration into database-stored JSON also enabled configuration changes without application deployments.

What matters to me

A shared foundation should make everyday development easier: understandable patterns, reusable building blocks, and less repeated maintenance.

03 / PERSONAL PROJECT

CORTEX · OBSIDIAN / COUCHDB / DOCKER

A notebook that keeps
context close at hand.

Cortex is my personal knowledge system: plain Markdown notes available across devices and accessible to the AI tools I use. I integrated existing tools into a workflow that keeps context from getting lost in chat histories.

Obsidian↔CouchDB↔Markdown mirror
Inside the project +

The approach

Obsidian provides the editing experience. Self-hosted LiveSync synchronizes notes through CouchDB, while a headless container maintains a Markdown mirror for tools that work with files.

Operational choices

CouchDB is the source of truth; the mirror can be regenerated. Private network access, sync monitoring, and backups support the workflow. Notes include conventions so tools can find relevant context and make focused changes.

My contribution

This is integration and operational work built on existing open-source tools. The engineering challenge is making the pieces work together and understanding where synchronization, persistence, and recovery can fail.
